## 測試情境

### 情境：用 code5 產生 FastAPI 網誌系統

使用者透過 code5 下達指令：

```
請用 fastapi 幫我產生一個網誌系統
```

code5 代理會：
1. 將提示詞送給 LLM
2. LLM 回覆包含 `<shell>` 指令來建立 Python 檔案（FastAPI 部落格）
3. 代理執行 shell 指令，在本地產生部落格程式碼
4. 確認產生的檔案可執行，並通過 FastAPI TestClient 測試

## 測試方式

### MockClient 測試（單元測試）

- 用 MockClient 模擬 LLM 回覆包含 `<shell>` 指令
- 代理執行後檢查是否成功產生 blog_app.py 等檔案
- 用 FastAPI TestClient 測試產生的 API 端點

### 真實 LLM 測試（整合測試，選擇性）

- 設定 `TEST_LLM=1` 環境變數時啟用
- 實際呼叫 NVIDIA API 產生部落格系統
- 驗證產生的程式碼能正常運作

## 技術設計

### 檔案結構

| 檔案 | 說明 |
|------|------|
| `tests/test_blog.py` | pytest 測試（Mock + 可選 LLM） |
| `test_blog.sh` | 執行測試的腳本 |

### 測試的部落格功能

產生的 FastAPI 部落格系統應包含：

- `GET /posts` - 列出所有文章
- `POST /posts` - 新增文章
- `GET /posts/{id}` - 取得單篇文章
- `PUT /posts/{id}` - 更新文章
- `DELETE /posts/{id}` - 刪除文章

## 實作重點

1. MockClient 需回傳足夠的 shell 指令來建立完整部落格
2. 測試需在暫存目錄進行，避免影響專案檔案
3. 支援 `TEST_LLM=1` 環境變數切換到真實 LLM 測試
4. 真實 LLM 測試需設定 `NVIDIA_API_KEY`
