# Code5 v0.6 功能規劃

## 版本資訊

- 版本: 0.6 (2026-05-06)
- 日期: 2026-05-06
- 主要更新: /bg 修復 + 指令寫入 history + /bglog + LLM 串流輸出

## 概述

修復 `/bg` 背景執行影響全域 stdout/stderr 的問題，並將所有系統指令 (`/xxx`) 納入歷史記錄。新增 `/bglog` 查看背景任務輸出。LLM 回應改用串流輸出，無需等待完整回應即可看到輸出。

## 新功能

### LLM 串流輸出

LLM 回應現在使用串流方式輸出，無需等待完整回應即可看到回應內容。

```
> 幫我寫一個 hello world
Hello wor
ld!
```

**實作方式**：
- `LLMClient.generate_stream()` 改為 async generator
- `NVIDIAClient.generate_stream()` 即時 yield 每個 chunk
- Agent 收到每個 chunk 時立即輸出並 flush

### /bglog - 查看背景任務輸出

使用 `/bg <prompt>` 執行背景任務後，可用 `/bglog <n>` 查看輸出。

```bash
/bg 幫我寫一個伺服器    # 背景執行
/bglog 5               # 查看前 5 個背景任務輸出
```

**輸出格式**：
```
=== 背景任務輸出 ===
#1 (完成):
[Agent 回應內容...]

#2 (進行中):
[進行中] 幫我寫一個網頁

#3 (錯誤):
[錯誤] RuntimeError: 429 Too Many Requests
```

**狀態說明**：
- `進行中`：任務正在執行，顯示 prompt
- `完成`：任務成功完成，顯示輸出
- `錯誤`：任務失敗（如 API 限速），顯示錯誤訊息

## Bug 修復

### /bg stdout/stderr 污染問題

**問題**：`/bg` 使用 `os.dup` 將 stdout/stderr 導入 `/dev/null`，造成全域 fd 被污染，導致後續指令輸出異常。

**解決方案**：改用 `StringIO` 局部替換，不影響全域 fd。
```python
from io import StringIO
output_buffer = StringIO()

async def run_bg():
    old_stdout = sys.stdout
    old_stderr = sys.stderr
    try:
        sys.stdout = output_buffer
        sys.stderr = output_buffer
        await current_agent[0].run(prompt)
    finally:
        sys.stdout = old_stdout
        sys.stderr = old_stderr
        output = output_buffer.getvalue()
        bg_outputs[task_id] = output
```

### 指令未寫入 history

**問題**：系統指令 (`/help`, `/history`, `/log` 等) 執行後不會寫入歷史記錄。

**解決方案**：將 `memory.update` 移入 `handle_command` 內部，所有指令都會自動寫入。

### 參數需求變更

為避免大量輸出，`/history`、`/log`、`/bglog` 現在需要指定 `<n>` 參數：

```bash
/history 10    # 查看前 10 筆提問
/log 10        # 查看前 10 筆記錄
/bglog 10      # 查看前 10 個背景任務輸出
```

## 行為變更

1. `/bg <prompt>` 執行後會寫入 history（而非寫兩次）
2. 所有 `/xxx` 指令都會出現在 `/history` 中
3. `/history`、`/log`、`/bglog` 需指定 `<n>` 參數
4. 背景任務輸出儲存於 `bg_outputs`，可隨時用 `/bglog` 查看
5. LLM 回應使用串流輸出，即時顯示不等待
