# Code5 v0.7 更新日誌

## 版本資訊

- 版本: 0.7 (2026-05-06)
- 日期: 2026-05-06
- 主要更新: 移除 /bglog、修復 /log 顯示、指令不再寫入 history、SQLite WAL 模式

## 概述

移除有問題的 `/bglog` 指令，修復 `/log` 重複顯示的問題。系統指令 (`/xxx`) 不再寫入資料庫，只儲存真正的對話內容。SQLite 改用 WAL 模式避免讀寫鎖定。

## Bug 修復

### /bg 完成後 /log 卡住

**問題**：`/bg` 完成後執行 `/log` 會卡住，懷疑是 SQLite 鎖定或 `task.result()` 造成。

**解決方案**：
1. SQLite 啟用 WAL 模式，支援讀寫並行
2. `check_pending_tasks()` 移除 `task.result()` 呼叫，只檢查 done 狀態

### /log 重複顯示對話

**問題**：`/bg` 完成後，`/log` 顯示兩次相同的 LLM 回覆。

**原因**：
1. `handle_command` 對 `/bg xxx` 指令呼叫 `memory.update`，將指令寫入 DB
2. 實際執行時 `agent.run("xxx")` 又寫入一次 prompt 和回覆

**解決方案**：將 `memory.update` 移出 `handle_command`，改為在 `run_once` 的訊息處理區塊中，只有非指令內容才寫入。指令 (`/xxx`) 不再寫入 DB。

### /log 顯示系統指令

**問題**：`/log` 會顯示 `/history`、`/bg` 等系統指令。

**解決方案**：`/log` 現在跳過所有以 `/` 開頭的內容，只顯示真正的對話。

### /bglog 移除

**原因**：`/bglog` 實作有 bug 且很少使用。

**移除內容**：
- `handle_command` 中的 `/bglog` 處理區塊
- `/bglog` 說明文字（CLI help 和內部 help）
- `bg_outputs` 參數
- `test_bglog_shows_output` 和 `test_bglog_requires_n` 測試

## 行為變更

1. `/bglog` 指令已移除
2. `/` 指令不寫入 history 或 log（只有真正對話內容會儲存）
3. `/bg xxx` 只儲存 "xxx" 作為 prompt，不是 "/bg xxx"
4. SQLite 使用 WAL 模式，讀寫可以並行

## 新增測試

| 測試 | 說明 |
|------|------|
| `test_log_skips_commands` | /log 不顯示 / 開頭的指令 |
| `test_commands_not_saved_to_history` | / 指令不會寫入 history |
| `test_bg_saves_only_prompt` | /bg 只儲存實際 prompt，不包含前綴 |

## 檔案異動

- `src/code5/__main__.py` - 移除 /bglog、指令不寫入 DB、簡化 check_pending_tasks
- `src/code5/db.py` - 啟用 WAL 模式 (`PRAGMA journal_mode=WAL`)
- `tests/test_integration.py` - 新增 3 個測試，移除 2 個 /bglog 測試
